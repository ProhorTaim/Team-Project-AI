# Аналитика стека проекта Team Project AI

Таблица описывает весь стек проекта — от языков программирования до внешних эндпоинтов:
зачем каждая технология используется и что она делает в проекте, а также почему не была выбрана альтернатива.

| Технология | Почему (зачем используется и что делает в проекте) | Преимущества (почему не альтернатива) |
|---|---|---|
| HTML5 | Каркас всех страниц: топбар, поле ввода идеи, блок результатов анализа, сетка карточек архива проектов. Семантические теги (`header`, `nav`, `main`) задают структуру документа. | Вместо JSX/шаблонизаторов (React, Vue, Pug): проекту не нужна реактивность фреймворка — страницы статичны, а чистый HTML не требует сборки и работает везде без компиляции. |
| CSS3 (кастомный, без фреймворков) | Отвечает за весь внешний вид: светлая/тёмная темы через CSS-переменные, параллакс-сетка фона, размытие (`backdrop-filter`), адаптив под телефоны и планшеты через медиа-запросы, стилизация ползунков и тумблера темы. | Вместо Bootstrap/Tailwind: фреймворки тянут десятки килобайт чужого CSS и навязывают свой дизайн; кастомный CSS дал точный контроль над темами и эффектами при меньшем весе страницы. |
| JavaScript (Vanilla, без фреймворков) | Вся логика фронтенда: навигация между вкладками, переключение темы с сохранением, загрузка JSON-данных, двухшаговый вызов LLM, отрисовка карточек, анимации появления результатов. | Вместо C++: C++ — язык системного программирования, в браузере он не выполняется напрямую; для веба нужен JS (или компиляция через WebAssembly, что избыточно для DOM-логики). Вместо TypeScript/React: проекту хватает vanilla JS — нет сложной реактивности, а отказ от сборки упрощает деплой на статический хостинг. |
| Fetch API | Выполняет все сетевые запросы: загрузка `projects.json`, `config.json`, `triggers.json`, промптов и POST-запросы к `/api/chat` для анализа идеи. | Вместо XMLHttpRequest: Fetch — современный стандарт с промисами и более чистым синтаксисом; XHR — устаревший API с громоздкими колбэками. Вместо Axios: лишняя зависимость ради того, что браузер уже умеет из коробки. |
| localStorage | Хранит выбранную пользователем тему (светлая/тёмная), чтобы оформление сохранялось между визитами. | Вместо cookies: cookies уходят на сервер с каждым запросом и требуют парсинга строки; localStorage проще, вместительнее (5 МБ) и не нагружает сеть. Вместо серверной сессии: не требует бэкенда и базы данных ради одной настройки. |
| matchMedia (`prefers-color-scheme`, `prefers-reduced-motion`, `pointer`) | Определяет системную тему при первом визите, отключает параллакс при `prefers-reduced-motion` и на тач-устройствах. | Вместо JS-опроса настроек или сторонних библиотек: нативный API браузера, ноль зависимостей, мгновенный отклик на системные настройки пользователя. |
| JSON (`projects.json`, `config.json`, `triggers.json`) | Формат всех данных: архив проектов (названия, амбиции, функции, годы), конфигурация модели (`model`, `maxTokens`, `minSimilarity`), триггеры фильтрации бессмысленного ввода. Легко читается и правится вручную. | Вместо базы данных (PostgreSQL/MongoDB): архив — статичный набор из ~10 записей, СУБД потребовала бы сервер и усложнила деплой; JSON-файлы раздаются хостингом как статика. Вместо XML/YAML: JSON нативно парсится в JS через `response.json()` без дополнительных библиотек. |
| Markdown (промпты `system.md`, `filter.md`) | В этих файлах хранятся системные инструкции для LLM: правила фильтрации похожих проектов и правила подробного анализа идеи. Промпты отделены от кода, их можно править без изменения JS. | Вместо хардкода строк в JS: промпты длинные (до 150+ строк), в коде они мешали бы чтению логики; отдельные файлы проще рецензировать и версионировать. Вместо базы промптов: избыточно для двух фиксированных инструкций. |
| Node.js (Vercel Serverless Function, ESM) | Среда выполнения файла `api/chat.js`: принимает POST от фронтенда, подставляет серверный API-ключ и проксирует запрос к OpenRouter. | Вместо PHP/Python-бэкенда: один язык (JS) на клиенте и сервере — не нужно держать два стека; serverless-функция деплоится вместе с фронтендом одной командой. Вместо выделенного сервера (Express/Nginx): нет постоянно висящего процесса — функция стартует только на время запроса. |
| Эндпоинт `/api/chat` (собственный прокси) | Скрывает секретный `OPENROUTER_API_KEY` от браузера: фронтенд шлёт сообщения сюда, а ключ подставляется только на сервере из переменных окружения. Также валидирует метод (только POST) и нормализует ответ LLM. | Вместо прямого вызова OpenRouter из браузера: ключ пришлось бы вшить в публичный JS, и его украли бы за минуты. Вместо полноценного REST-бэкенда: один эндпоинт закрывает единственную серверную задачу проекта. |
| OpenRouter API (`https://openrouter.ai/api/v1/chat/completions`) | Внешний LLM-эндпоинт, выполняющий тяжёлую работу: отбор релевантных проектов по смыслу и генерацию развёрнутого анализа идеи. Вызывается дважды на один запрос пользователя. | Вместо прямого API одного вендора (OpenAI/Anthropic): OpenRouter даёт единый интерфейс и бесплатные модели; смена модели — одна строка в `config.json`, а не переписывание интеграции. Вместо локальной модели: не нужен GPU-сервер и его обслуживание. |
| LLM-модель (`openrouter/free`, по умолчанию `minimax/minimax-m3:free`) | Конкретный «движок» анализа: понимает русский язык, сравнивает идею с архивом, пишет рекомендации по заданной HTML-структуре. | Вместо платных моделей (GPT-4, Claude): бесплатная модель закрывает задачу студенческого проекта с нулевым бюджетом на API. Вместо эвристик без ИИ (поиск по ключевым словам): только LLM понимает смысл и находит похожие проекты по проблеме, а не по совпадению слов. |
| Двухшаговый pipeline (filter → system) | Архитектура анализа: шаг 1 (filter-промпт) отбирает топ похожих проектов с процентами, шаг 2 (system-промпт) строит подробный разбор только по ним. Экономит токены и повышает точность. | Вместо одного гигантского запроса: передача всех полных описаний проектов за раз переполнила бы контекст и размыла бы ответ; фильтрация сначала — точнее и дешевле. Вместо клиентского скоринга (TF-IDF/косинусная близость): эмбеддинги требуют ML-инфраструктуры, а LLM-фильтр уже есть в стеке. |
| Собственный markdown→HTML конвертер (в `script.js`) | Преобразует ответ LLM (заголовки `##`, списки `-`, `**жирный**`) в безопасный HTML для вставки на страницу, собирает карточки похожих проектов в сетку. | Вместо marked/DOMPurify из npm: конвертер на ~30 строк покрывает ограниченный формат ответов; внешняя зависимость ради трёх правил разметки не оправдана. Вместо `innerHTML` сырого ответа: парсер попутно вычищает пустые узлы и собирает карточки в единую сетку. |
| Переменные окружения (`OPENROUTER_API_KEY`) | Хранят секретный ключ вне кода: Vercel подставляет его только в serverless-функцию, в репозитории ключа нет. | Вместо ключа в коде/конфиге: попадание ключа в git означает его компрометацию и чужой расход квоты API. Вместо файла секретов на диске: env-переменные — штатный механизм Vercel, ничего лишнего разворачивать не нужно. |
| Vercel (хостинг статики + serverless) | Платформа деплоя: раздаёт HTML/CSS/JS как статику, выполняет `api/chat.js` как serverless-функцию, даёт HTTPS и демо-домен `team-project-ai.vercel.app`. | Вместо обычного VPS/shared-хостинга: не нужно настраивать сервер, SSL и деплой-скрипты — пуш в git сам обновляет демо. Вместо GitHub Pages: Pages не умеет в серверные функции, а проекту нужен прокси для сокрытия API-ключа. |
